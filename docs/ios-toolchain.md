# iOS toolchain notes

`ios/` is generated by `npx expo prebuild` and is gitignored, so everything
here lives in the repo root. Since the move to Expo SDK 58 that is just a
`Gemfile` — the deployment-target config plugin and the `bin/ios` wrapper that
SDK 54 needed are both gone, and `npx expo run:ios` works again.

The short version, from a clean clone:

```bash
npm install
bundle install
npx expo run:ios
```

## `Gemfile` — pinning CocoaPods' dependencies

Running `pod install` against a current Ruby can fail before it does any work:

```
ArgumentError - unknown keyword: quirks_mode
```

`cocoapods-core`'s gemspec pins `activesupport >= 5.0, < 8`, so CocoaPods
always resolves activesupport 7.x. That version's JSON encoder still calls
`JSON.generate(jsonified, quirks_mode: true, max_nesting: false)`, and the
`json` gem removed `quirks_mode:` in 3.0. Nothing triggers it until something
calls `#to_json` — which `expo-modules-autolinking` does on every install.
activesupport 8 dropped the call, but the CocoaPods pin puts it out of reach.

Whether you hit this depends on which `json` your Ruby resolves, so it is not
reproducible on every machine. The `Gemfile` holds `json` on 2.x so the keyword
always exists. Use `bundle exec pod install`, not bare `pod install`; Expo's
CLI does this for you automatically once a `Gemfile` is present. `Gemfile.lock`
is committed so everyone resolves the same versions.

## Things SDK 58 fixed, kept here for the archaeology

### The iOS 27 launch crash

An app built against the iOS 27 SDK must adopt the UIKit scene lifecycle or
UIKit kills it at launch:

```
Application failed to launch: UIScene life cycle is required for apps built
with this SDK. See "Transitioning to the UIKit scene-based life cycle"
```

SDK 54's template had no `UIApplicationSceneManifest` and no scene code, so the
app showed a black screen on iOS 27 while still running fine on iOS 26. SDK 58's
template generates `ios/Attend/SceneDelegate.swift` and the matching
`UIApplicationSceneManifest` in `Info.plist`, so there is nothing to configure.
(SDK 57 exposed `ios.enableSceneSupport` through `expo-build-properties` for
this; on 58 that property is a no-op.)

### Pod deployment targets

Xcode 27 refuses to build any target whose `IPHONEOS_DEPLOYMENT_TARGET` is
below iOS 15, and SDK 54 generated several pod *resource bundles* that declared
9.0–13.4, so a clean `pod install` produced a project that wouldn't compile.
`plugins/withPodMinimumDeploymentTarget.js` raised them in a `post_install`
hook.

SDK 58's Podfile sets `platform :ios, '16.4'` and nothing it generates lands
below 15.1, so the plugin was deleted. If a future pod reintroduces the problem,
scope any fix to `installer.generated_projects` rather than passing
`IPHONEOS_DEPLOYMENT_TARGET` on the `xcodebuild` command line — that would also
hit `AttendWidget`, whose Live Activity code needs `ActivityViewContext`
(iOS 16.1+), and the widget would stop compiling.

### `expo run:ios` and the simulator

Xcode 27 removed the standalone `Simulator.app`; the simulator UI is now
DeviceHub (`/Applications/Xcode.app/Contents/Applications/DeviceHub.app`,
bundle id `com.apple.dt.Devices`). `@expo/cli` 54.x resolved the simulator by
the old name, so `npx expo run:ios` aborted before building anything, and
`bin/ios` drove `xcodebuild` and `xcrun simctl` directly instead.

DeviceHub support shipped in `@expo/cli` 56 ([expo/expo#46757]), so SDK 58
finds simulators on its own and `bin/ios` was deleted.

[expo/expo#46757]: https://github.com/expo/expo/pull/46757

## Troubleshooting

**`Unable to resolve module <some-package>` at the bundling step.** `node_modules`
has drifted from `package.json`. Run `npm ci`.

**`Unicode Normalization not appropriate for ASCII-8BIT` from `pod install`.**
CocoaPods unicode-normalizes the project path and Ruby reads it as binary when
the locale isn't UTF-8. Set `LANG=en_US.UTF-8`. Usually only bites in CI and
non-interactive shells.

**The app installs but shows a connection error.** The dev client needs the
bundler. Run `npx expo start --dev-client` in another shell. If port 8081 is
already taken by another checkout, pass `--port`.

**`expo prebuild` fails with `Cannot read properties of undefined (reading
'removeFromProject')`.** `@bacons/apple-targets` can't update the existing
`AttendWidget` target in place, so a second prebuild over an existing `ios/`
crashes. Always pass `--clean`. Still true on SDK 58 with apple-targets 5.0.0.

**Picking a simulator for iOS 27.** The iOS 27.1 runtime only accepts newer
device types; `xcrun simctl create` rejects an `iPhone 17` against it as
"Incompatible device". `xcrun simctl list devicetypes` plus trial and error is
the only way to find one that takes.
